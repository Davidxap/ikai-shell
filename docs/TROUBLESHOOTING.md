# Troubleshooting

Made from `bar/modules/bin/ito-health`. Run `ito-health` for the live report and `ito-health --fix all` to apply every offered fix.

| Log message matches | What it is | What it means | What to do | Fix |
|---|---|---|---|---|
| `Duplicate property name|Duplicate binding|Duplicated property` | A panel page declares the same thing twice | One of the Control Centre's pages has a property or a binding written twice, so that page fails to load and shows empty. | Copy the files back with the deploy step: the repository's version is the corrected one. If it comes back, send the report. | `ito-health --fix deploy` |
| `Cannot assign object of type|Cannot assign binding of type` | A widget or page uses a part in the wrong place | Something was put where the shell does not accept it, so that widget or page does not load (a blank spot or an empty page). | Copy the files back with the deploy step. If it comes back, send the report. | `ito-health --fix deploy` |
| `Error Reading Animated Image File` | Your own media effect file cannot be read | The picture or GIF chosen as the media effect is missing or is not a picture the shell can play. | Fix goes back to the Blood effect if the file is gone; choose another file on the Effects page. | `ito-health --fix pictures` |
| `Cannot open: file://\S*/\.(cache|config)/ito/(marks|effects)/\S*` | One of your own pictures is missing | A picture you chose (a mark, the seal's picture, a workspace picture or the media effect) is no longer where the shell looks for it, so that spot is blank. Its adapted copy lives in ~/.cache/ito/marks and is rebuilt from your original in ~/.config/ito/marks. | Fix rebuilds the adapted copies from your originals, and if a style or effect that depends on a picture that is gone, goes back to the default one. | `ito-health --fix pictures` |
| `Cannot open: file://\S*` | A picture file is missing | The shell tried to draw an image that is not on disk (or was given a folder instead of a picture), so that spot is blank. | Copy the art back with the deploy step. If it is one of your own marks, check the file in ~/.config/ito/marks. | `ito-health --fix deploy` |
| `Plugin widget (\S+) failed` | A widget failed to load | The named widget could not start, so it is missing from the bar until it is fixed. | Restore its folder from the repository and restart the shell. | `ito-health --fix plugins` |
| `Type (\S+) unavailable|is not a type` | A QML component could not be built | A file the shell needs failed to load, usually because of an error in it or in a file it imports. Everything that uses it is missing. | Restart the shell. If it comes back, look for the error just before it in this list. | `ito-health --fix restart` |
| `Property value set multiple times` | A property is assigned twice in one file | Two lines in the same QML object set the same thing. The object fails to load, so the widget or the whole bar disappears. | This is a bug in the file named. Send the report; it is a one-line change. | — |
| `Cannot assign to non-existent property` | A file sets a property that does not exist | A name is misspelt or belongs to another QML version. The object fails to load. | This is a bug in the file named. Send the report. | — |
| `Cannot read property '(\w+)' of null` | Something was used before it existed | A tooltip or panel ran before the bar it belongs to was ready. It happens for a moment while the shell starts or reloads and clears itself. | Nothing to do if it stops after start-up. If it keeps coming, restart the shell. | `ito-health --fix restart` |
| `Unable to assign \[undefined\] to` | A value was not ready yet | A control read a setting before it had loaded, and used its default for that moment. | Harmless once the panel is open. Nothing to do. | — |
| `TypeError|ReferenceError|is not a function` | A script raised an error | A widget's code did something that is not allowed, so part of it stops working. | Restart the shell. If it returns, send the report with the file named. | `ito-health --fix restart` |
| `suite marker|retire` | The bar engine refused to start | The engine checks that its files match a signature. After files change the signature is stale and it retires for good until it is rewritten. | Rewrite the signature and restart. | `ito-health --fix markers` |
| `qt\.multimedia\.ffmpeg|moov atom not found` | A media file could not be decoded | Something in the host shell (not an IKAI widget: none of ours use QtMultimedia) tried to open a video or audio file that is not a valid container. No IKAI file appears in this log line. | — | — |

Harmless, hidden from the report: A media player closed while it was being read, Two handlers for one remote command, A notification's picture could not be shown, A widget was replaced while it was working, Desktop portal, Bluetooth service, Graphics driver notice, A tray application's menu went away, A deprecated Qt call in Omarchy's own shell, A font resolved two sizes at once.
